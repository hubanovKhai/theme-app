# Міні-застосунок «Перемикач теми» на React Context API

Лабораторна робота з вивчення React Context API, кастомних хуків, роботи з `localStorage`, CSS-змінними, Zustand та тестування за допомогою Vitest.

## Виконані рівні складності

- **Рівень 1:** створено `ThemeContext`, `ThemeProvider`, кнопку перемикання теми та стилізовано компоненти `Header`, `Content`, `Footer`.
- **Рівень 2:** додано збереження стану в `localStorage`, кастомний хук `useTheme()` з перевіркою контексту, CSS-змінні через атрибут `data-theme` на `<html>` та іконки з `react-icons`.
- **Рівень 3:** реалізовано підтримку режимів `light`, `dark`, `system` (`matchMedia`), керування станом через `useReducer`, мемоїзацію (`useMemo`, `useCallback`), розділення контексту на два (`ThemeStateContext` та `ThemeActionsContext`), а також додано третю тему `blue` і випадаючий список.
- **Рівень 4:** написано unit-тести на Vitest + React Testing Library, додано альтернативну реалізацію на **Zustand** для порівняння, синхронізацію між вкладками через подію `storage` та скрипт у `index.html` для усунення миготіння теми при завантаженні.

## Порівняння Context API та Zustand

| Критерій | React Context API | Zustand |
| :--- | :--- | :--- |
| **Обсяг шаблонного коду** | Більший (створення контекстів, провайдера, редьюсера, мемоїзація) | Мінімальний (один файл `create(...)` без провайдерів) |
| **Обгортка дерева** | Обов'язковий `<ThemeProvider>` у `main.jsx` | Не потребує провайдера |
| **Кількість рендерів** | Без розділення контекстів ре-рендеряться всі споживачі; з розділенням — лише підписники на стан | Компоненти підписуються атомарно через селектори (`state => state.theme`), зайві рендери відсутні |
